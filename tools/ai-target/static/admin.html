Overview

Two realistic AI assistants share one deliberately vulnerable architecture: Northbridge Bank (Nora, retail banking) and Meridian Health (Clara, patient portal). Point Vantyr at the public target, run a mission, then compare its findings with the answer key and the live hit log. Turn on hardening and guardrails, then run it again to show the difference.

Public target

The target listens on its own port (:8090) with no login so a red-team tool can reach it. Expose it on a lab network only, never through the public tunnel. Set the address Vantyr (or its on-prem runner) will use.

Vantyr scope — ai_endpoints

Paste into the mission scope. Covers chat in OpenAI, Ollama and raw formats plus both MCP servers. The AI Supply Chain agent probes the same host and port for the exposed model server, vector DB and leaked key. Add http://host:8090 as a web target too, so Web App discovery finds the AI endpoints on its own.

LLM backend

    
Both assistants call one OpenAI-compatible chat endpoint with tool calling. Bundled Ollama, a vLLM server and any OpenAI-compatible gateway all work.
      Use a model that supports tool calling: qwen2.5:3b is the smallest reliable one; qwen2.5:7b or llama3.1:8b work better.
